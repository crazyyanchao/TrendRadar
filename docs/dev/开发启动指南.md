# TrendRadar 开发启动指南

面向开发者的本地运行、调试与日常刷新文档。覆盖两种启动方式（本地 Python / Docker）、AI 配置加载机制、常用运维命令与已知问题。

## 一、组件与端口一览

| 组件 | 入口 | 默认端口 | 说明 |
|------|------|---------|------|
| **选题终端**（TOPIC TERMINAL） | `python -m trendradar.webapp` | `8090` | 个性化 TOP10 选题 + 实时热榜 + AI 研判，本项目的主界面 |
| **主抓取管线** | `python -m trendradar` | — | 定时抓取全平台热榜/RSS，写入 `output/`，生成 HTML 报告 |
| **Web 报告服务器** | Docker cron 模式自动启动 | `8080` | 托管 `output/html/` 报告 |
| **MCP 服务** | `python -m mcp_server.server` | `3333` | AI 对话 / MCP 客户端接入 |

端口由环境变量控制：`TERMINAL_PORT`（默认 8090）、`WEBSERVER_PORT`（默认 8080）、`MCP_PORT`（默认 3333）。

> 表中 `python -m ...` 均为示例入口，实际运行时统一加 **`uv run`** 前缀，原因与等价写法见「三、依赖安装」。

## 二、环境准备

- [uv](https://docs.astral.sh/uv/)（推荐，自动管理 Python 版本）
- Python ≥ 3.12（`uv sync` 会自动下载）
- Docker（可选，仅使用 Docker 方式启动时需要）

## 三、依赖安装

```bash
# 在项目根目录执行；会自动安装匹配的 Python 与全部依赖
uv sync
```

**为什么统一用 `uv run` 启动？**

依赖与 Python 版本都由 uv 管理在项目根目录的 `.venv/` 中，而系统 Python（如 Windows 常见的 3.11）低于项目要求（`pyproject.toml` 中 `requires-python = ">=3.12"`），且不含任何项目依赖——因此裸 `python -m trendradar` 会报版本或模块缺失错误。以下三种写法等价，任选其一：

```bash
uv run python -m trendradar                  # ① 推荐：uv 自动激活 .venv
.venv/Scripts/python -m trendradar           # ② Windows：直接调用 venv 解释器
.venv/bin/python -m trendradar               # ②' Linux/macOS 路径
source .venv/Scripts/activate && python -m trendradar   # ③ 先激活 venv 再裸 python
```

后文所有 `python -m ...` 命令统一使用 `uv run` 前缀。

## 四、本地启动（方式一，开发推荐）

### 1. 启动选题终端（8090）

```bash
# 推荐：webapp 会自动加载 docker/.env 与 .env 中的 AI 配置，无需手动注入
uv run python -m trendradar.webapp --host 127.0.0.1 --port 8090 --open-browser

# 等价入口
uv run python -m trendradar --serve
```

启动成功标志（stdout）：

```
📡 TrendRadar 选题终端 v6.x.x
地址: http://127.0.0.1:8090/
配置文件加载成功: config/config.yaml
[选题终端] AI 打分服务已就绪
[选题终端] AI 研判服务已就绪
```

### 2. 抓取最新资讯数据

```bash
uv run python -m trendradar
```

无参数运行完整管线：抓取热榜 + RSS → 分析 → 生成 HTML 报告。未配置通知渠道时不会推送。

### 3. 刷新 AI 选题（TOP10）

修改了 `output/terminal/profile.json` 中的兴趣/关键词后，触发一次 AI 重打分：

```bash
curl -X POST http://127.0.0.1:8090/api/score/run
# → {"ok": true, "data": {"task_id": "t_xxxxxxxx"}}

# 轮询任务
curl http://127.0.0.1:8090/api/tasks/t_xxxxxxxx
# → {"data": {"state": "done", ...}}
```

webapp 也会在读取接口时按冷却期自动重打分（`TERMINAL_AUTO_RESCORE=1` 时）。

## 五、Docker 启动（方式二）

```bash
cd docker
docker compose up -d          # 使用 docker/.env 的配置，启动 trendradar + trendradar-mcp
```

- 镜像：`wantcat/trendradar:latest`、`wantcat/trendradar-mcp:latest`
- 访问：选题终端 `http://localhost:8090`，报告 `http://localhost:8080`，MCP `http://localhost:3333`
- 容器内管理终端：`docker exec -it trendradar python manage.py start_terminal` / `stop_terminal` / `terminal_status`

## 六、AI 配置与加载机制

AI 配置集中放在 **`docker/.env`**：

```dotenv
AI_ANALYSIS_ENABLED=true
AI_API_KEY=sk-...
AI_MODEL=deepseek/deepseek-v4-flash   # LiteLLM 格式: provider/model
AI_API_BASE=                          # 可选，自定义端点
```

**加载顺序与生效规则：**

1. **选题终端（webapp）**：`server.py` 的 `run()` 会依次加载 `["docker/.env", ".env"]`，用 `os.environ.setdefault` 注入（已存在的环境变量优先，文件不覆盖）。所以本地直接跑 webapp 无需手动 export。
2. **主抓取管线**：只读 `config/config.yaml` 的 `ai:` 段与进程环境变量，**不会自动加载 docker/.env**。
3. 优先级：进程环境变量 > `.env` 文件 > `config.yaml`。

> ⚠️ **已知缺口**：本地用 `python -m trendradar` 直接跑主管线时，若 AI Key 只存在 `docker/.env` 且未手动注入环境变量，管线内的 AI 分析/翻译会报 `未配置 AI API Key` 而降级。Docker 部署无此问题（compose 会把 .env 注入容器环境）。选题终端的 TOP10 打分不受影响。

## 七、常用 API（选题终端）

| 接口 | 说明 |
|------|------|
| `GET /api/status` | 数据源状态灯（绿/黄/红） |
| `GET /api/profile` | 个性化配置（昵称/关键词/兴趣） |
| `GET /api/hotlists?limit=30` | 多平台实时热榜 |
| `GET /api/rss?hours=24&limit=120` | 权威新闻源时间流 |
| `GET /api/score/top10` | TOP10 选题（含 `engine`: `ai`/`keyword`） |
| `POST /api/score/run` | 触发 AI 重打分 |
| `GET /api/tasks/{tid}` | 异步任务状态 |

设置了 `TERMINAL_TOKEN` 后，写接口需携带请求头 `X-Terminal-Token`。

## 八、数据与目录结构

| 路径 | 内容 |
|------|------|
| `config/config.yaml` / `timeline.yaml` / `frequency_words.txt` | 主配置 / 调度时间线 / 频率词 |
| `output/news/YYYY-MM-DD.db` | 热榜新闻库（含 AI 标签/分类结果） |
| `output/rss/YYYY-MM-DD.db` | RSS 文章库 |
| `output/html/` | 生成的最新/历史报告 |
| `output/terminal/profile.json` | 终端个性化配置（不写回 `config/`） |
| `output/terminal/top10.json` | 最近一次 TOP10 快照 |
| `output/terminal/research/` | 单条选题 AI 研判缓存 |
| `output/terminal/notes.json` | 用户笔记（与研判缓存分离） |

## 九、常见问题与坑

**1. 端口 8090 被占用（WinError 10048）**
旧 webapp 进程未退出。找到并结束进程：
```bash
netstat -ano | grep ":8090"
taskkill //PID <pid> //F
```

**2. 不要在 bash 里直接 `source docker/.env`**
`CRON_SCHEDULE=*/30 * * * *` 中的 `*` 会被 shell 展开成当前目录文件名，报 `_image: command not found`。需要取值时用 eval 只取需要的键，或直接依赖 webapp 的自带加载：
```bash
set -a && eval "$(grep -E '^(AI_|TERMINAL_|WEBSERVER_)=' docker/.env)" && set +a
```

**3. 日志显示「AI 打分服务未启用」**
检查 TOP10 接口的 `engine` 字段（`GET /api/score/top10`）。若为 `keyword`/`unavailable`：确认 `docker/.env` 中 `AI_API_KEY`、`AI_MODEL` 是否有效，或 `config.yaml` 的 `ai.api_key` 是否已设置。

**4. 后台运行看不到输出**
Python 在非 TTY（重定向到文件）时 stdout 是块缓冲。判断服务是否正常请以接口响应、`output/` 数据文件时间戳为准，而不是空日志。

**5. 开发预览（不抓取）**
仓库内置样例库，可用调试锚点直接看页面效果：
```bash
TERMINAL_DATE=2026-08-27 uv run python -m trendradar.webapp --open-browser
```

**6. 状态灯为红色**
当天无抓取记录或数据超 24 小时未更新。先跑一次 `uv run python -m trendradar`。

## 十、日常刷新流程（速查）

```bash
# 1. 确保终端在跑
uv run python -m trendradar.webapp --host 127.0.0.1 --port 8090

# 2. 抓最新数据
uv run python -m trendradar

# 3. 改过兴趣后刷选题
curl -X POST http://127.0.0.1:8090/api/score/run
```
